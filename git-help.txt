2. Git vs GitHub
Git

Git is software installed on your computer.

It tracks changes to your files and keeps a history of your work.

GitHub

GitHub is an online service where your Git repository is stored.

Think of it as:

Git     = Version control tool on your computer
GitHub  = Online home for your Git repository
VS Code = Where you write your code

5. Linux SSH Setup

We checked the SSH directory:

ls -la ~/.ssh


Then created an SSH key:

ssh-keygen -t ed25519 -C "hello@ajitujagare.com"


The key was saved as:

~/.ssh/id_ed25519
~/.ssh/id_ed25519.pub


Important:

id_ed25519
    = PRIVATE KEY
    = NEVER SHARE

id_ed25519.pub
    = PUBLIC KEY
    = Can be added to GitHub


We added the Linux public key to GitHub.

Then tested the connection:

ssh -T git@github.com


Successful result:

Hi ajit-ujagare-lab! You've successfully authenticated,
but GitHub does not provide shell access.


This confirmed:

Linux → SSH → GitHub ✅

8. What Does git clone Mean?

git clone means:

Copy an existing GitHub repository onto a computer for the first time.

Example:

git clone git@github.com:ajit-ujagare-lab/azure-data-engineering.git


Use git clone when setting up the project on a new computer.

Do NOT repeatedly clone the same project.

Once the project already exists on the computer, use:

git pull

16. Why Did We Create .gitkeep?

Git does not track empty directories.

Therefore, we created:

python/.gitkeep
sql/.gitkeep
pyspark/.gitkeep
azure/.gitkeep
projects/.gitkeep


This allows Git to keep the empty folders in the repository.

Once real files are added, .gitkeep files are generally no longer necessary.

17. Git add

Example:

git add .


Meaning:

Prepare all changed files for the next commit.

The . means the current directory and its contents.

18. Git commit

Example:

git commit -m "Create project folder structure"


Breakdown:

git
    = Use Git

commit
    = Save a checkpoint

-m
    = Provide a message

"Create project folder structure"
    = Description of the changes


A commit is saved in your local Git history.

It is NOT automatically sent to GitHub.

27. Switching Between Linux and Windows

Suppose you work on Linux today.

After finishing:

git add .

git push

Tomorrow, on Windows:

cd ~/projects/azure-data-engineering
git pull


Now Windows has the latest changes.

The same works in reverse.

28. Important Rule When Switching Computers

Before starting work on another computer:

git pull


Before switching to another computer:

git push


Simple habit:

Finish → Commit → Push
Switch computer
Pull → Continue

29. What If I Get a New Computer?

You can use the same GitHub account.

On the new computer:

Install Git
     ↓
Configure Git
     ↓
Create SSH key
     ↓
Add public SSH key to GitHub
     ↓
git clone
     ↓
Start working


For example:

git clone git@github.com:ajit-ujagare-lab/azure-data-engineering.git


One GitHub account can have multiple SSH keys:

GitHub Account
     |
     ├── Linux SSH key
     ├── Windows SSH key
     └── New Computer SSH key

VS Code
   ↓
Git
   ↓
GitHub


is the preferred workflow.

Version history
Commits
Branches

Collaboration
Ability to undo/recover changes
32. SSH Passphrase

Our SSH keys are protected with a passphrase.

When Git asks:

Enter passphrase for key...


enter the passphrase you created for that machine.

This is NOT your GitHub password.

SSH passphrase
    ↓
Protects your private SSH key

GitHub password
    ↓
Used for GitHub website/account authentication


We decided to keep the SSH passphrase protection rather than removing it.

Later, ssh-agent can be configured to reduce repeated passphrase prompts.

33. LF / CRLF Warning

On Windows you may see:

LF will be replaced by CRLF
the next time Git touches it


This is usually a line-ending warning, not an error.

Linux commonly uses:

LF


Windows commonly uses:

CRLF


Because this project is used on both Linux and Windows, Git may warn about line endings.

The warning does not normally mean your Python or SQL file is broken.

34. Security Rules

NEVER commit sensitive information to GitHub.

Do NOT put these in the repository:

Passwords
API keys
Azure client secrets
Connection strings
Private SSH keys
.env files containing secrets
Access tokens
Certificates/private credentials


Especially NEVER upload:

~/.ssh/id_ed25519


The private SSH key must remain private.

The .pub file is the public key.
